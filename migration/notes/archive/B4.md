# B4: Warp port of the tree solver (B1) and inverse statics (B2), results

Package: `heliades/sim/gpu/`:

| file | contents |
|---|---|
| `sim.py` | TreeSimGPU |
| `kernels.py` | one kernel source, float32/float64 instances |
| `layout.py` | flattened multi-tree |
| `inverse.py` | GPU inverse, Sturm count, bisection, critical E |
| `contact.py` | B3 slot |

Design: `docs/sim/GPU.md`. Tests: `tests/heliades/test_sim_gpu.py` (19 tests, ~12 s warm; skipped
without CUDA). Benchmark: `scripts/gpu_benchmark.py`. No file outside `heliades/sim/gpu/`, the docs,
the test, the script and these notes was changed.

**Design in one paragraph.**
* **Layout.** Global body index sorted by (level, rank, env): every depth level is one
  contiguous range over the whole batch. A shared topology is body-major `g = i*B + e`, which
  gives coalesced access. Different topologies use the same code with no padding.
* **Up sweep.** One launch per level, with all bulk terms (inertia, bias, gravity stiffness,
  implicit gyroscopic terms, damping, point forces, sphere penalties, joint spring) fused in.
  Children are pulled by a CSR segmented sum, with no atomics.
* **Down sweep.** One launch per level, with the state update and the forward kinematics of the
  new state fused in.
* **Graphs.** 54 launches per step for the tomato, captured as a CUDA graph per key, with no host
  sync inside a step. settle/solve_static bookkeeping also runs on the device.
* **Inverse.** B2's inverse fuses loads, the local Newton solve, rest rotations, Hessian blocks
  and the 3×3-pivot Sturm elimination into one leaf→root sweep.

## Precision findings

* fp32 does **not** break the stiff cases. The 1000:1 and 10⁴:1 mass ratios match fp64 to about
  1e-7 m, because ABA factorises the mass matrix exactly and the pivots stay well conditioned.
  Energy monotonicity is unchanged.
* Ratios ≥ 3·10⁴:1 on B1's chain exceed the quaternion spring's capacity. They are chaotic on the
  CPU in fp64 too, and the GPU and CPU diverge from 1e-16 seeds within 1 s. This is a model
  limit, not a precision limit.
* fp32 limits:
  * static increments floor at one ulp, so `solve_static(tol < 5e-8)` does not converge;
  * B2's round trip reaches 5e-7 instead of 1e-12;
  * round-off seeds unstable equilibria (E = 5e8 inverse rest: 0.7 mm in 3 s against 1e-12 m in fp64).
* Policy (mixed by task): fp32 for RL/dataset rollouts; fp64 for tight statics, inverse round
  trips and parity. Both builds come from one source.

## Bugs / pitfalls found on the way

* Warp closure kernels break with `from __future__ import annotations`, because annotations
  become strings that do not resolve the closure types. `kernels.py` must not use it.
* `atomic_max` drops NaN, so a blown-up env reported "settled". The reductions now map NaN/inf to
  +BIG.
* The graph cache key must include the contact hook. A graph captured before `sim.contact` was
  set silently skipped the hook.
* The B1 CPU sphere penalty fails on the tomato with large stiff spheres (a 12 cm sphere at
  k = 3e3: singular D by step 7). This is B1 behaviour and a motivation for B3's Delassus contact.

## Limitations

* `newton_static` and `stiffen_to_stable` are not ported.
* Heterogeneous gaps:
  * `inverse_statics_gpu` raises NotImplementedError for heterogeneous batches (the kernels are
    generic; only result packing is missing);
  * `state` and `leaf_vertices` raise for heterogeneous batches (use `env_state`).
* No wp.Tape gradients: state is updated in place.
* fp64 throughput is bound by consumer-GPU fp64 units.
* Small-B latency: 54 dependent launches per step. B = 1 is 0.2 ms; a persistent per-tree kernel
  with level barriers would cut it.

## Contact interface (B3 not merged at the time of B4)

`sim.contact = solver`, and `solver.solve(sim, h)` runs inside the step graph between the
factorisation and the integration sweep. The primitives are:

* `slot_free_motion` (free accelerations);
* `factor_response_device` (Δu̇ for spatial body forces; k of them give the k×k Delassus operator
  in O(kn));
* `slot_apply` (fold λ into ũ; the regular down sweep integrates).

See GPU.md §8 for the full pipeline B4 expects: detect → free → Delassus → PGS → apply.
